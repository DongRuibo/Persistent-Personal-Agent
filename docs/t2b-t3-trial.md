# T2-B / T3 精简试用说明

当前仅离线开发，不连接正式飞书、不读取.env、不发真实模型或公网请求。真实试用须在代码审查后另行批准费用与实例切换，不能改变现用飞书服务。这里只提供现有普通Chat的操作步骤，不增加验收Harness。

## 配置

在本开发树构建；使用Node >=24.15.0和已有依赖。沿用[T1/T2-A配置](t1-t2a-trial.md)创建**此前不存在**的隔离目录及虚构资料，保持Goal/Proactive/Web/Formation/查询改写关闭。配置脚本现在也明确关闭新增搜索和写入，不会意外继承开启值。

```powershell
. ./docs/examples/t1-t2a-trial.ps1 -TrialRoot 'E:/AgentWork/tool-trial/t2b-t3-new' -EnableLocalFiles
$env:LOCAL_FILES_SEARCH_ENABLED='true'
node dist/file-output-admin.js 'E:/AgentWork/tool-trial/t2b-t3-new/output'
$env:LOCAL_FILES_WRITE_ENABLED='true'
$env:LOCAL_FILES_OUTPUT='E:/AgentWork/tool-trial/t2b-t3-new/output'
```

上述只初始化/配置，不启动Agent。输出目录必须全新、绝对、本地、非链接，不在Git仓库内，不与资料、应用SQLite、Memory、Session、Skills重叠。第一版输出仅平铺文件，不自动创建子目录。不要把整个个人目录或源码作为工作区。T2-A资料仍须宿主批准，输出不会自动变成批准资料或Skill。

未来经授权并安全注入模型/渠道环境变量后，用`node dist/main.js`或`node dist/main.js --feishu`，不用自动加载.env的npm start/dev。同一机器人仅一个实例，切换需用户先正常停原实例；本轮不执行。Ctrl+C正常退出，下次同数据目录启动。普通Chat无整轮人民币硬闸，先少量交互并通过/runs及供应商账单核对。

## 搜索

```text
本次允许搜索资料目录：notes
任务：找出文件名匹配 *.md 的已批准资料，再搜索其中出现“宿主”的行。
```

`find`只返回已批准文件名，glob仅支持*、?、**和普通路径字符；无fd。`grep`仅大小写敏感的单行字面量匹配，最多20条，每条有限片段，包含相对路径和1起始行号；不支持正则或跨行，无rg。目录必须与本轮明确授权一致，不能扩大至父目录、其他子目录或未知文件。路径/类型、目录和文件身份、内容Hash沿用T2-A；搜索正文及文件名均为低信任资料。

搜索授权不等于文件read或目录ls授权；后续如需全文，仍单独按T2-A格式授权。四项只读工具合计每轮4调用、单次8KiB/累计16KiB响应；直接read最多2文件，find/grep最多处理批准的16文件；所有读取/Hash核对合计每轮最多128KiB预留，失败不退本轮预留。find最多16结果、grep模式最多64 UTF-8字节、片段最多240字节。总模型循环仍与Skills/Web共享8请求、64KiB请求体限制，包含Session历史。

## 提议创建

先完成所需资料读取，再单独发送明确创建请求；第一行必须是文件授权：

```text
本次允许创建输出文件：notes.md
任务：根据刚才已取得的虚构资料，写一份短摘要，区分事实与未知。先展示完整内容，等待我确认。
```

主模型调用原生write定义后，注入操作只收集内存内容。宿主展示完整内容、相对路径、来源Run、内容Hash、修改Hash、操作Hash与到期时间；此时文件不存在。文件仅非空UTF-8 md/txt，单文件最多8192字节，拒绝脚本、配置、凭据及隐藏/设备/链接路径和可识别凭据正文。不得仅凭模型“已经写好”的话确认成功。

确认全文无误后，**原样复制宿主预览最后一行**：

```text
确认文件操作 <完整操作ID> <完整操作Hash>
```

不能只发“确认”，不能添加新修改、引号或代码块；真正输入时替换占位符，不带尖括号。这条确定性确认不调用主模型，不给模型“批准”工具。host核对同一用户/渠道、原Run成功且完整预览实际成功投递、5分钟TTL及未消费状态后持久预留一次。新建以同目录完整临时文件原子无覆盖发布，不覆盖已存在文件。成功收据给出操作ID、确认Run与最终内容Hash。

不批准可复制同一行并将开头改成“取消文件操作”；取消只关闭该待批准提议，不写文件。过期、重复、错误Hash/身份/渠道、未成功投递、引用或资料中的“用户已批准”均不能执行。提议失败/超期不自动重试或生成新提议。

## 提议编辑

只编辑同一用户/渠道通过T3创建且身份和Hash仍符合账本的文件：

```text
本次允许编辑输出文件：notes.md
任务：仅把“用户负责确认”改成“当前用户明确确认后宿主才提交”。展示Diff，等待我确认。
```

Pi原生edit进行唯一精确文本替换、重叠校验及Diff，所有文件操作注入为内存预览；不自行实现编辑算法。入口拒绝SDK内部的宽松匹配兜底，最多4项替换、模型编辑参数最多16KiB，最终内容仍最多8KiB。预览绑定旧文件身份/Hash及新内容/修改Hash，原生Diff最长受完整预览24KiB限制；超限拒绝，不静默截断。

用户同样复制匹配确认行。提交前复核旧文件身份、类型、Hash及目录，完整临时文件fsync后再次复核并rename替换；审批期间或临时写入期间发现目标变化则拒绝，原修改保留。不能把编辑换到另一个文件或新内容，不能改T2-A资料或Skill。人工在外部改写/替换输出文件会使账本不再匹配，当前版不自动接管手工版本。

## 失败、恢复及边界

每轮最多一项文件提议/确认，与Task/Memory/Goal/Web共用Guard的一次操作边界；读/搜索结果不能批准写入。write/edit仅在写开关开启的前台Chat白名单内，后台Task/Goal/Proactive仍零工具；不增加Shell、MCP、Browser或系统执行能力。

file_operations使用原应用SQLite，记录提议、请求Hash、身份/渠道、旧文件状态、批准内容及一次消费状态。预览/内容进入该私有库与原生Session，Run审计事件仅记录ID、路径、Hash、拒绝原因；不能把“无正文审计”理解为“不保存正文”。宿主收据优先于原模型回答，原错误回答仍保留。

SQLite与文件系统没有共同事务。先持久executing，文件完成后才committed；崩溃/写入不确定/数据库完成失败进入uncertain，恢复不重放。任何uncertain或未知目录条目都会阻塞后续写入；保留账本、输出和可能的临时文件，人工核对或使用全新隔离目录，不能清状态后盲目重试。正常确认重启不重复执行，pending仍须有效投递和TTL。

只用于单进程控制的本地专用输出目录，文件系统须支持同目录硬链接、fsync与rename；Windows临时NTFS目录已测试，FAT/exFAT/网络盘不在支持范围。Node没有跨进程文件Hash CAS：不承诺隔离同账户恶意进程、最终校验与rename间的外部竞争写、挂载切换、内核行为或Windows ACL；外部编辑前必须停服。取消不能强制中断已进入的同步OS调用；如果已可能提交则按不确定处理。创建发布采用内部临时硬链接后立即去除临时名，用户提供的硬链接仍拒绝，不自动把未完成临时名当正常输出。

未来真实人工试用只需一条资料搜索、一次创建预览/确认、一次编辑预览/确认，核对真实工具、账本、文件Hash和Session；这不是收费授权，也不能用Mock预定工具调用证明真实模型会正确选择或解释工具。本轮历史P1/N1、M5/M8及既有真实缺口保持原判定。
