# V2.1 第一阶段：Memory Retriever 实施与评测

日期：2026-10-21。Git 基线：`dcec1f4e55e3de816245e0983b8cbfff75efd0b3`，开始时本地/远端 main 一致、工作区干净。用户已授权将本批实现、测试和验收记录提交并推送main，准确SHA与同步结果见Git历史及交付回复。

只使用虚构资料与系统临时目录；没有打开正式 Memory、Task、Session，没有改正式 .env、启动用户服务或发飞书消息。用户随后明确授权最多80次/两轮只读查询改写，已完成两轮44次请求。下文保留词法基线，再单独记录真实改写；生成回答、真实拒答、完整真实模型Pi执行与手机联调均未执行。模拟改写只验证接线与隔离，不计入语义质量。

## 路线选择

| 路线 | 复杂度/依赖 | 中文与实体效果 | 成本/延迟 | 维护取舍 |
| --- | --- | --- | --- | --- |
| A 词法、实体/字段/日期、类型与排除约束 | 低，无依赖 | 能修排序和精确约束，不能解决无共同词 | 0 API；线性磁盘校验 | 本阶段默认 |
| B 当前问题只读改写 + A | 中，复用现有模型，无新服务 | 有机会扩大同义召回；改写本身仍可能错 | 每轮低置信度最多1次，512输出token/5秒；非跨轮缓存 | 可选，默认关闭；两轮实测改善召回，但仍有误匹配 |
| C Embedding + 关键词 | 中高；需选模型、向量版本和索引 | 可能提高召回，仍需实体/无答案校验 | 写入/查询成本及维护更多 | 本阶段不引入；不用独立向量数据库 |

选择 A + 可选 B，先把可靠约束、可追踪结果和评测做稳。没有新增模型、依赖、数据库迁移，也没有改变写操作授权。默认词法仍未达到同义目标；可选改写的真实结果单独记录，不能据小样本宣布检索质量完整验收。

## 100/1000条性能与存储取舍

完整资源数据见 [before](v2.1-performance-before.json) 与 [after](v2.1-performance-after.json)：cold打开、CPU、RSS/heap差值和进程累计峰值。RSS受GC/缓存与同进程上一组影响，不能从两次短跑推导稳定内存节省，更不等于VPS配置。
最小优化仅去掉一次 buildContext 内重复 all()/repair。1000条约50ms级同步读仍保留，可短暂阻塞事件循环；当前单用户没有依据引入跨轮正文缓存/向量库/复杂文件监听。查询改写开启时每轮首次还需一次准备校验，性能表是默认关闭时的检索路径，不计主模型与网络。
每次从Markdown重建/验证仍可发现损坏、磁盘删除及SQLite触发器错误；不以缓存掩盖故障。selected只保留ID、每次重新读取当前版本。授权、文件权限、Hash、唯一写入/删除语义都未改变。

## Context、权限与复现

- 默认 `MEMORY_QUERY_REWRITE=false`。true时公开异步context Hook调用现有 ModelRuntime.completeSimple：只传当前原始问题的JSON，无工具/历史/Memory正文。最多3个短改写、每轮1次、5秒、512输出token、无重试；不跨轮缓存，实体和日期等仍取原始问题。它只提供检索词，不能产生写权限。
- 召回使用词项IDF与低权重中文字串，约束英文具名项目/小姓氏式人名、日期与常见排除；类型优先、字段事实线索排序；未知字段保留uncertain。存在一般语言能力边界，不声称完整实体识别。
- Context优先含字段支持的记录；没有支持时保留最多2条主题相关资料并标insufficient/uncertain，再结合本轮工具显式读取的当前ID，最多5条。正文截断必须继续核对，不把supported当确定答案。
- 继续Pi公开context返回副本，不追加Session。工具只返回收据，Task/Memory写入仍经过原Guard。后台独立Session无工具。改写失败有memory_rewrite事件及降级提示；无法读取/验证文件仍中止而非绕过校验。
- 可复现：`npm run typecheck`、`npm run build`、`npm test`、`npm run eval:memory`；性能：`node --import tsx scripts/benchmark-memory.ts`。均不自动加载.env、不连接外部模型。
- 真实收费验收仅获得授权后：`node --env-file-if-exists=.env --import tsx scripts/evaluate-memory.ts --live --allow-paid`；每轮40题，低置信度才请求，硬上限40次，无重试。输出保留queries/Token/耗时/失败；两轮已完成，结果见下一节。可用 `--replay=<真实评测JSON>`回放已记录改写，回放不算新真实模型评测。
- 成本预算：用户已批准最多80次虚构问题改写（最多两轮），实际44次后停止；已报告用量估算约0.0194元，失败调用用量未知，不冒充账单。参考[硅基流动公开价](https://www.siliconflow.cn/pricing)，实际以供应商账单为准。默认关闭额外成本=0；不会消耗剩余36次授权额度来继续调试。

## 失败样本、回归及人工验收

- 原题仍漏：更愿意读哪种文字、拿铁方糖、机器人断线。最终留出漏：讨论记录先写决定还是待办、烧脑工作时段；Nacre UI language误排历史发布；阿青联系方法误排设备恢复。日语/Kotlin等未列入字段启发式，可能召回对但证据标签保守。没有根据这些留出题新增答案或同义词映射。
- 本轮重跑84项自动化通过，0失败/跳过，约6.19秒；typecheck/build/eval退出0。新测试覆盖原始约束不能被改写换掉、实体前缀、ISO/年份日期、多实体比较、每轮一次、失败/中止、动态版本/删除、真实Pi SDK+模拟模型的全新Session/后台隔离及临时投影。现有Feishu/Task/Guard/存储回归继续运行。
- 模拟测试不能证明真实语义提升；真实收费改写已完成，尚未运行真实生成拒答、手机端检索、真实隐私资料、并发负载、10k条或Linux/VPS。
- 人工最小验收：先用非敏感虚构记忆保存“测试项目数据库”“饮品偏好”；停服，换全新SESSION_DIR保留同一Memory，启用可选改写后用同义问法询问，不在问题中给答案；核对memory_context的id/version/evidence/预算及memory_rewrite耗时和同Run模型用量。
- 再问不同项目配置、未记录的下次发布日期；更新后查新版本，删除后再换全新Session确认不命中。可安排一条普通提醒核对后台只读命中和原会话未混入；本阶段不擅自做这些正式数据操作。
- 先交付审查，再决定是否修复已发现的实体/字段风险或扩大检索方案；不自动开始记忆形成、Observer、Skill、Outbox或其他开发。
